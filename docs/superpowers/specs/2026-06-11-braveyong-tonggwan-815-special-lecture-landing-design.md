## 1. 배경 & 목표

8월 15일부터 전자상거래 전용 통관플랫폼이 개통되며, **전자상거래업자 부호**가 없으면 구매대행·배대지·판매중개 셀러의 통관이 막힌다. 부호 발급의 진짜 병목은 **사업자용 무료 인증서**이고, 이를 푸는 핵심 노하우(개인계좌 연결 기업뱅킹 가입 → 통장 0개 + 인증서 0원)를 용팀장이 라이브 특강으로 판매한다.

- **목표**: 단일 목적 랜딩 1장으로 6/21(일) 라이브 특강 결제 전환.
- **상품**: 6/21(일) 온라인 라이브 특강 (라이브 단독).
- **가격**: 190,000원 + 부가세 10% = **209,000원(부가세 포함)**.
- **결제**: 결제선생(PayMint) 청구서 자동발송.
- **이행(fulfillment)**: 결제 완료 → 카카오톡 오픈채팅방 입장 링크 안내 → 6/21 라이브.
- **마감 압박**: 정원 제한 + 결제 마감일 + 8.15 역산 데드라인(3중).

### 성공 기준
1. 신청폼(이름·연락처) 제출 → 결제선생 청구서가 정상 발송된다.
2. 결제 **승인 이후에만** 오픈채팅 입장 링크가 노출된다(비결제자 링크 유출 차단).
3. 기존 198만원 강의 페이지·결제 흐름은 **무손상**으로 유지된다.
4. 페이지에 성과 보장·"무조건 된다" 표현이 없고, 면책 고지가 포함된다.

### 수정 파일 (수술적, 기본 동작 보존)
- `app/api/paymint/send-bill/route.ts` — `productKey` optional 입력 추가. `lib/products.ts`에서 상품 조회. **미지정 시 기존 course 198만원 동작 유지**(default).
- `components/payment-dialog.tsx` — `productKey` prop 추가(default = course). 안내 문구를 prop으로 주입(특강용 "결제 후 카톡방으로 6/21까지 챙긴다"). 디스플레이 `amount`는 그대로 prop.
- `app/api/paymint/callback/route.ts` — 승인 콜백 수신 시 productKey별 후속 안내(오픈채팅) 트리거 지점 추가(상세는 §5).

## 4. 결제 → 오픈채팅 입장 흐름

```
[신청폼: 이름·연락처]
  → POST /api/paymint/send-bill  { productKey: "tonggwan-815" }
  → 결제선생 청구서 (URL 우선, 불가 시 카톡 fallback)
  → 결제 완료
      ├─ (server) callback 승인 수신 → 로그 + 오픈채팅 안내 트리거(§5)
      └─ (client) /815/complete?bill_id=XXX
              → read-bill 로 결제상태 검증
              → PAID 면 오픈채팅 입장 링크 노출
              → PENDING 이면 "결제 확인 중" + 카톡 재발송 안내
```

**링크 유출 차단 원칙**: 오픈채팅 링크는 페이지 본문 어디에도 노출하지 않는다. 오직 (a) read-bill로 결제 확인된 `/815/complete`, (b) 결제 승인 콜백 후 발송되는 안내에서만 공개한다.

## 5. send-bill / callback / 오픈채팅 안내 (구현 메모)

### lib/products.ts
```ts
export const products = {
  course: { name: "용감한용팀장 AI셀링 실전반 오프라인 1기", amount: 1_980_000 },
  "tonggwan-815": {
    name: "용감한용팀장 8.15 통관대응 라이브 특강",
    amount: 209_000,
    openchatUrl: process.env.NEXT_PUBLIC_TONGGWAN_OPENCHAT_URL || "",
    liveAt: "2026-06-21 20:00",       // 운영입력
    payDeadline: "2026-06-20T23:59:59+09:00", // 운영입력
    capacity: 50,                      // 운영입력
  },
} as const
```

### send-bill
`productKey`로 `products[key]` 조회 → `productName`/`amount`를 거기서 가져온다. 미지정 시 course 기본값.

### 오픈채팅 안내(결제 승인 후)
- **1차(권장)**: `/815/complete`가 `read-bill`로 결제완료를 확인하면 즉시 링크 노출. 결제선생이 결제 후 return URL을 지원하면 그 URL을 `/815/complete`로 설정. (← **결제선생 return URL 지원 여부는 구현 시 확인** — 미지원 시 결제 다이얼로그 완료 화면의 "입장 링크 확인" 버튼으로 `/815/complete` 진입)
- **2차(백업)**: 콜백 승인 시 오픈채팅 입장 안내를 카톡으로 자동발송(`kakao_notice_messages.txt` 틀 활용). bill_id↔구매자 매핑이 필요하면 send-bill 시점에 최소 메타(billId, productKey, phone)를 경량 저장(Vercel KV 등)하고 콜백에서 조회. **이 영속화 방식은 구현 계획에서 확정.**

## 6. 운영 입력값 (env/config, 확인 필요)

| 항목 | 제안 default | 비고 |
|---|---|---|
| 라이브 일시 | 2026-06-21(일) 20:00 | 시간·길이(예 90분) 확인 |

| 환불 정책 | (확정 필요) | 라이브 단독이라 §7 리스크 참조 |

## 7. 카피 가이드 · 리스크

### 톤/금지(브랜드 규칙)
- 직설·도발 → 반드시 근거 + 오늘 할 일로 마무리.
- **금지**: 성과 보장, "무조건 된다", 검증 안 된 단정. 원본 "정확성 3원칙"(무조건 없음 / 막히면 빠질 길 있음 / 공동·금융인증서 정명칭)을 카피에 반영.
- 면책 고지 필수: 법률·세무·관세 일반정보, 은행 정책 수시 변경, 실행 직전 재확인.

### 리스크
1. **라이브 단독 = 불참자 보호장치 없음.** 당일 불참 시 0원 손해 → 클레임 위험. 페이지에 다시보기를 파는 대신, **운영 안전장치**(불참 시 다음 회차/자료 안내 등)를 환불 정책·FAQ로만 명시 권장.
2. **은행별 편차**: "되는 은행/막히는 경우"를 단정하지 않도록 카피에서 조건부 표현 유지.
3. **결제선생 return URL 미지원 가능성**: §5의 2차 백업(콜백→카톡)으로 커버.
