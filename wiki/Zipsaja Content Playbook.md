# Zipsaja Content Playbook

> 집사자(zipsaja) 콘텐츠의 댓글싸움 골격, 후크 공식, 대립축, 감정 아크, 캐러셀·릴스 구조, 파이프라인·게시 규칙. 진입점은 [[Zipsaja Index]]. 톤은 [[Zipsaja Persona]], 수치는 [[Zipsaja Data Findings]].

## 1. 콘텐츠 골격

표준 전개 순서 (캐러셀 10장 / 릴스 30초 공통, 압축률만 다름):

```txt
공감(노력/안전 선택 인정)
→ 데이터 충격(예상 못한 숫자)
→ 격차 산수(큰 숫자 두 개 대비)
→ 규제/구조 원인(정책 룰 제시)
→ 면책(네 탓 아니다)
→ 댓글 질문(양자택일 강요)
```

**캐러셀 10장 role 시퀀스** (storyboard.json, 부모찬스 번들 기준)
1. cover — 후크 한 줄(대립/반전 압축)
2. setup — 상황·인물 세팅
3. formula — 정책/규제 룰 제시
4–5. scenario A vs B — 큰 숫자 두 개 대비
6–7. table / amplify — 실거래 표로 격차 증폭
8. limit — 격차의 의미 한 방 정리
9. risk — 면책/방어 슬라이드
10. cta — 댓글 유도 질문(dark CTA 비주얼)

**릴스 30초 6비트** (각 4~6초): 후크 → 인물 대비 → 규제 룰 → 시나리오 A → 시나리오 B → 댓글 질문.

## 2. 후크 공식

**[성실한 노력/안전한 선택]을 인정 → [예상 못한 숫자 충격]으로 뒤집기.** "~했는데(인정), ~됐다/갈렸다(반전)" 역접 구문이 핵심.

반복 패턴 4종:
- **"X 했는데, Y 더 필요/멀어졌다"** (노력 vs 격차)
- **"같은 Z인데, 갈렸다"** (동일조건 vs 결과차이)
- **"A는 ~했고, B는 ~가져갔다"** (세입자 vs 집주인)
- **"~줄 알았는데, ~는 안 알려줬다"** (안전 착각 폭로)

실제 후크 예시:
1. "3억 모았는데, 어제보다 1억 더 필요해졌대."
2. "같은 월급인데, 집 보는 동네가 갈렸다."
3. "나는 보증금 올려줬고, 집주인은 집값 오른 걸 가져갔다."
4. "성실하게 모았는데, 더 멀어졌다."
5. "노력 차이인 줄 알았는데, 시작금 차이였다."
6. "전세가 안전한 줄 알았는데, 기회비용은 안 알려줬다."
7. "투기 잡는다더니, 신혼부부 현금부터 더 필요해짐."
- 릴스 메타 후크: "이건 댓글 싸움 좀 날 것 같아." (싸움을 명시적으로 예고)

## 3. 댓글싸움 유도 메커니즘

핵심: **한쪽 편을 들지 않고, 정확히 둘로 갈리는 대립축을 숫자로 제시한 뒤 "너는 뭐라고 봐?"로 선택을 강요.** 콘텐츠마다 4개 안팎의 미니 싸움축을 깔고, 끝에 양자택일 질문 1개를 박는다.

| 대립축 | 왜 댓글이 붙나 |
|---|---|
| 부모찬스 vs 자수성가 | "부모 도움도 능력" vs "그건 노력 아님" — 도덕적 정당성 다툼 |
| 실수요자 vs 투기꾼 / 대출규제 찬반 | "대출 막아야 집값 잡힘" vs "실수요자만 죽음" — 정치·진영 프레임 |
| 눈 낮춰라 vs 생활권은 못 자른다 | "서울 고집이 문제" vs "직장·육아가 서울인데?" — 라이프스타일 정당화 |
| 전세(안정) vs 매매(자산) | "전세가 제일 안전" vs "상승분 포기한 것" — 과거 선택 후회 |
| 집주인 vs 세입자 | "집주인도 리스크 졌다" vs "세입자는 기회비용 냈다" — 계급 구도 |
| 저축 vs 집값 속도 | "더 아꼈어야지" vs "노동소득으론 속도 안 맞음" — 자기책임 vs 구조책임 |
| 강남 vs 동북권(용산·광진·노도강) | 통념을 데이터로 깨고(용산 +18.5% vs 강남 -2.5%) 지역 자존심·매수타이밍 논쟁 |

**마무리 양자택일 질문 예시**
- "이건 집값 잡는 정책이야, 신혼부부 잡는 정책이야?"
- "이게 노력 차이야, 시작선 차이야?"
- "전세 5년, 안정이었을까 기회비용이었을까?"
- "1. 대출 더 막아야 집값 잡힌다 / 2. 전세 공급부터 풀어야 서민이 산다 — 댓글로 숫자 보고 싸워보자."

## 4. 감정 아크

```txt
공감(인정) → 충격(데이터) → 박탈감/분노(격차 확인)
→ 자기방어 해소(네 탓 아님) → 분노의 외부화(구조·정책)
→ 발화 욕구(댓글)
```

핵심 장치는 **면책 슬라이드**: "네가 게을렀던 게 아니라 집값 속도가 빨랐던 거다", "누가 잘못했다는 얘기가 아냐." 독자의 자책을 시스템 분노로 전환시켜, 방어적 침묵 대신 댓글로 분출하게 만든다.

## 5. CTA / 마무리 패턴

세 가지 닫기:
1. **양자택일 댓글 질문** (기본형)
2. **면책 후 질문** — "부모 욕하자는 게 아니라 시작금이 얼마나 크게 작동하는지 보자는 거야 → 노력으로 커버 가능하다고 봐?"
3. **자료 미끼 + 키워드 댓글** — "서울 25개 구 엑셀/PDF 자료 필요하면 댓글에 '전세난' 남겨." (댓글 수 자체를 lead magnet으로)

공통: 마지막은 단정 결론이 아니라 **열린 질문**. 끝에 출처/면책 한 줄(기준·필터·"실제 가능액은 LTV·DSR·금리 따라 다름") 고정.

## 7. 제작 파이프라인 (zipsaja-remotion-v1)

오케스트레이터 `zipsaja-remotion-orchestrator`가 `pipeline-state.json`을 읽고 다음 단계를 결정. 단계 스킬:

1. **zipsaja-brief** → 훅·앵글·CTA 브리프(`brief.md`)
2. **zipsaja-data-fetch** → SSH `hh-worker-2`의 `proptech_db`에서 25개 구 실거래 dataset(`data.json`)
3. **zipsaja-storyboard** → 30초 릴스 장면 구성(`storyboard.json`)
4. **zipsaja-remotion-render** → Remotion 9:16, 30초 전체 릴스(`reels/`)
5. **zipsaja-carousel-render** → Jinja2 + Puppeteer로 1080×1350 캐러셀 PNG(`carousel/`)
6. **zipsaja-attachments** → Excel(`seoul-price-data.xlsx`) + PDF(insights)
7. **zipsaja-captions** → IG/Threads/LinkedIn 캡션(`captions/`)
8. **zipsaja-package-qa** → 정합성·규격 QA, publish-ready 점검

신규 zipsaja 릴스는 Remotion만 사용(HyperFrames는 보관용). 공통 구조·표준 bundle은 [[HowZero Content Pipeline]] 참조.

## 8. 게시 워크플로우 (Zernio)

- **명령 순서(개별 제출)**: IG Reel → IG Carousel → Threads Carousel. `--instagram-media both`는 dry-run/저위험 1차에만(한 payload 409 시 combined가 멈춤).
- **IG Reel**: `reels/zipsaja-reel-30s-audio-mapped-ig-safe.mp4` 우선(1080×1920, 9:16, H.264, 30fps, 30s). 커버는 `publish-ready/instagram-reel-cover.png`. 핵심 텍스트는 중앙 4:5 안쪽.
- **IG Carousel**: 음악 불가 → `publish-ready/instagram-carousel/slide-*.png`(1080×1350, 4:5) Feed.
- **Threads Carousel**: `publish-ready/threads-carousel/slide-*.png`, 본문은 `captions/threads.txt` **2줄 자극적 훅만**(첫 줄=충격/반전 숫자, 둘째 줄=양자택일·도발+댓글 유도). 3줄 이상·긴 설명·해시태그 금지, topic은 `--topic-tag`. (사용자 피드백 2026-06-12)
- **409 중복 보호**: `details.existingPostId` 조회 — `publishing/processing`이면 이미 생성된 것. 재게시 요청 시 첫 훅·문장 순서·CTA를 구조적으로 변경(공백/문장부호만 변경은 무효).
- **기록**: 결과는 번들 루트 `publish-state.json`에 platform별 postId·status·platformStatus·mediaCount·timestamp 누적.
