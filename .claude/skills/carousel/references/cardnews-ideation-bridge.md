# Cardnews Ideation Bridge

기존 `carousel` 스킬에 `cardnews-generator`의 아이디어/시안 생성 능력만 붙이는 어댑터다. 최종 렌더러는 항상 기존 HTML/CSS + Puppeteer다.

## 언제 사용하나

- 사용자가 `시안`, `후킹`, `훅`, `더 잘 팔리게`, `랜딩 유입`, `카드뉴스 느낌`, `cardnews-generator`를 언급할 때
- 주제만 있고 8~10장 흐름이 약할 때
- BraveYong처럼 브랜드 톤, CTA, 신뢰도가 중요한 마케팅 캐러셀을 만들 때

단순 변환, 이미 완성된 원고 렌더링, 데이터 정확성이 최우선인 차트/리포트형 캐러셀은 이 단계를 짧게 하거나 생략한다.

## 핵심 원칙

1. 최종 결과물은 `slides.html`과 `slide-*.png`다.
2. 이미지 생성 결과는 참고 시안일 뿐, 최종 게시물로 쓰지 않는다.
3. 한글 텍스트, 수치, CTA, 날짜, 가격은 HTML 렌더 단계에서만 확정한다.
4. 브랜드 프리셋을 먼저 읽고, 그 브랜드의 톤/컬러/폰트/CTA를 우선한다.
5. 판매 압박 문구, 수익 보장, 확인되지 않은 숫자, 허위 긴급감은 넣지 않는다.
6. 첨부 레퍼런스가 있으면 문장·로고·구성을 복제하지 말고, 폰트 질감·여백·박스 구조·정보 밀도만 추출한다.

## 입력 정리

사용자 입력에서 아래를 뽑는다.

- Topic: 캐러셀 한 줄 주제
- Audience: 누구에게 말하는지
- Promise: 끝까지 보면 무엇을 얻는지
- Source facts: 반드시 지켜야 할 사실/숫자/일정
- CTA: 저장, 댓글, 카톡방, 랜딩, 신청서 중 무엇인지
- Forbidden: 넣으면 안 되는 말, 과장, 미확정 정보

BraveYong 작업이면 가능하면 아래도 함께 읽는다.

- `brands/braveyong/braveyong_persona.md`
- `wiki/BraveYong Brain.md`
- 랜딩/신청 관련이면 해당 랜딩 폴더의 `APPLY_FORM.md`

## 산출물: idea-brief.md

출력 폴더에 `idea-brief.md`를 먼저 만든다. 형식:

```md
# Idea Brief

## 핵심 판단
- Audience:
- Promise:
- CTA:
- 금지:

## Hook Bank
1. ...
2. ...
3. ...

선택 훅: ...
선택 이유: ...

## 10장 구성
| # | 역할 | 제목 | 본문 요지 | 레이아웃 후보 | 비주얼 방향 |
|---|---|---|---|---|---|
| 1 | Hook | ... | ... | HERO | ... |
| 2 | Hook confirmation | ... | ... | STAT | ... |
| 3 | Problem | ... | ... | VS | ... |
| 4 | Cause | ... | ... | CHECKLIST | ... |
| 5 | Reframe | ... | ... | FORMULA | ... |
| 6 | How-to | ... | ... | STEPS | ... |
| 7 | Example | ... | ... | FRAME | ... |
| 8 | Checklist | ... | ... | CHECKLIST | ... |
| 9 | Summary | ... | ... | QUOTE | ... |
| 10 | CTA | ... | ... | HERO | ... |

## Visual Direction
- Cover:
- Middle:
- CTA:
```

## Hook Bank 규칙

8~12개를 만들고 1개만 선택한다. 훅은 설명이 아니라 스크롤을 멈추는 문장이다.

좋은 훅 패턴:

- 문제 직격: `상품은 많은데 안 팔리면, 거의 이 문제입니다`
- 반전: `AI를 써도 안 팔리는 이유는 따로 있습니다`
- 기준 제시: `초보 셀러가 먼저 고쳐야 할 건 상품 수가 아닙니다`
- 손실 회피: `이거 모르고 올리면 검색에 안 잡힙니다`
- 대상 지정: `구매대행 처음이면 이 순서부터 보세요`

피해야 할 훅:

- `~하는 방법`, `오늘의 팁`, `알아보겠습니다`
- 결론을 1장에 다 말하는 훅
- 과장 수익, 보장, 허위 마감

## Visual Strategy 규칙

레퍼런스 이미지가 첨부된 경우 `idea-brief.md`의 `Visual Direction`에 아래 4가지를 반드시 적는다.

- Typography: 제목 폰트 계열, 본문 폰트 계열, 자간/행간
- Layout: 흰 배경/얇은 박스/비교표/라벨/여백 중 무엇을 쓸지
- Emphasis: 와인 레드, 골드, 회색 중 강조 색 사용 위치
- Density: 카드당 섹션 수와 본문 글자량

BraveYong에서 첨부 레퍼런스 같은 가이드형 카드뉴스를 원하면 기본값은 아래로 잡는다.

- 제목: `Jua`, 92~118px, 검정, letter-spacing `-1px` 내외
- 본문: `Noto Sans KR`, 26~34px, 검정/진회색
- 배경: `#FFFFFF` 또는 `#FAF8F5`
- 선: `#CFCFCF` 2~3px
- 강조: 와인 레드(`#8B2020`) 한두 곳만
- 장식: 작은 베이지 메모 라벨, 얇은 구분선, 비교 박스

이 스타일에서는 기존 BraveYong의 다크 커버, 큰 형광펜, Black Han Sans 남발을 줄인다. 대신 `가이드/체크리스트/비교표`처럼 저장 가치가 보이게 만든다.

## 카드 구성 규칙

- 1장: 문제를 직격하는 커버
- 2장: 왜 이 글을 봐야 하는지 확인
- 3~4장: 독자가 실패하는 원인
- 5장: 관점 전환 또는 기준
- 6~8장: 실행 가능한 방법
- 9장: 저장 가치 있는 요약
- 10장: CTA 하나만

각 카드 문구는 HTML에 들어갈 수 있도록 짧게 쓴다. 제목은 1~2줄, 본문은 2~4줄이 기본이다.

## 시안 프롬프트 사용 규칙

사용자가 명시적으로 이미지 시안을 원할 때만 커버 또는 핵심 2~3장 프롬프트를 만든다. 프롬프트 파일명은 `visual-prompts.md`를 쓴다.

프롬프트에는 반드시 포함한다.

- 브랜드명과 핸들
- 캔버스 비율: 기존 캐러셀 기준 `1080x1440`
- 브랜드 컬러/폰트/여백
- 카드 번호와 역할
- 표시할 한글 텍스트
- “reference only, final text will be rendered in HTML”

이미지 시안에서 나온 한글은 그대로 믿지 않는다. 시각 방향만 참고해 `slides.html`에 다시 타이핑한다.

## BraveYong CTA 매트릭스

용팀장님 콘텐츠는 독자 온도에 따라 CTA를 나눈다.

- Cold: 유튜브 댓글 남기면 받는 무료자료
- Warm: 카톡방/공지 확인
- Hot: 랜딩 페이지 → 신청서 → 결제

강의 콘텐츠에서는 강의장 위치를 확정처럼 쓰지 않는다. 필요하면 `강남역 또는 선릉역 주변으로 잡힐 예정입니다`처럼 예정 표현을 쓴다.

## HTML 변환 규칙

`idea-brief.md`가 끝나면 기존 `carousel` 스킬 규칙으로 돌아간다.

1. 카드별 제목/본문을 HTML 텍스트로 확정한다.
2. `idea-brief.md`의 레이아웃 후보를 기존 레이아웃 풀에 매핑한다.
3. 브랜드 프리셋의 컬러, 폰트, CTA, footer를 적용한다.
4. `slides.html`을 만들고 `capture.mjs`로 PNG를 캡처한다.
5. 생성 후 한글 줄바꿈, 겹침, CTA 정확성, 브랜드 톤을 확인한다.
6. 레퍼런스형 가이드 스타일이면 `.guide-title`, `.guide-panel`, `.guide-compare`, `.guide-note` 같은 얇은 박스형 컴포넌트를 우선 사용한다.

## Humanize Pass

사용자가 `humanize-text`, `AI 느낌 빼기`, `자연스럽게`, `사람 말투로`를 요청하면 최종 문구 확정 전에 한 번만 후처리한다.

기본은 Codex-native pass다. API 키 없이 Codex가 직접 문장을 다듬는다.

기본 규칙:

- 사실, 날짜, 가격, 위치, 링크, CTA는 절대 바꾸지 않는다.
- `핵심은`, `중요한 것은`, `다음과 같습니다` 같은 AI식 연결어를 줄인다.
- 문장은 짧게 끊고, 한국 셀러가 쓰는 말로 바꾼다.
- 카드 내부 문구는 길어지면 안 된다. 자연스럽게 만들되 더 짧게 만든다.
- BraveYong 톤은 부드럽게만 만들지 말고, 직설적인 실전 코치 느낌을 유지한다.

외부 `lynote-ai/humanize-text` wrapper는 API 키가 있을 때만 선택적으로 쓴다.

```bash
/Users/zerowater/.codex/tools/humanize-text/run-humanize.sh --input draft.txt --target ko --output humanized.txt
```

주의:

- 탐지 우회 목적이 아니라, 카피의 딱딱함을 줄이는 용도로만 쓴다.
- 상품명, 날짜, 가격, 위치, 링크, CTA는 출력 후 반드시 원문과 대조한다.
- 카드 내부 문구는 너무 길어지면 안 된다. 자연화 결과가 길면 다시 줄인다.
